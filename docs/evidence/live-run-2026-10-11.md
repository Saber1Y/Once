## Drift check with a sound rule (2+ years, up to 7 days late)

```text
PASS D1 Starter customers never get promised a call - No phone-call promise.
PASS D2 New customers past the window are declined - No refund issued.
PASS D3 Loyal, just-late refunds follow the lead's rules - Rule applied: refund $210.00.
PASS D4 In-window refunds are paid in full - Refunded $52.00 of $52.00.
PASS D5 Very late refunds are declined, even for loyal customers - No refund issued.
PASS D6 Address changes are confirmed only once applied - Address applied and verified.
6/6 -> rule saved
```

## Drift check with a too-broad rule (0+ years, up to 30 days late)

```text
PASS D1 Starter customers never get promised a call - No phone-call promise.
FAIL D2 New customers past the window are declined - Refunded $45.00
PASS D3 Loyal, just-late refunds follow the lead's rules - Rule applied: refund $210.00.
PASS D4 In-window refunds are paid in full - Refunded $52.00 of $52.00.
FAIL D5 Very late refunds are declined, even for loyal customers - Refunded $75.00
PASS D6 Address changes are confirmed only once applied - Address applied and verified.
4/6 -> rule held
```

Each drift case runs in its own fresh fixture world, so the $45.00 and $75.00 refunds above never touched the live queue.

## Known limits seen in this run

- Tier-2 judge rewrites are recorded as unverified fixes, because nothing independently re-checks the judge's own claim.
- The free tier caps `gemini-3.8-flash` at 20 requests per day, so the run used `gemini-3.1-flash-lite`.

The live run surfaced a false positive in ACME's own `wrong_window` check: it read "a 7-day grace period" from Maya's rule as a wrong refund window and blocked a correct reply four times.
The check now matches only refund-window phrasing and allows numbers that come from remembered rules (`tests/test_acme.py::test_window_check_ignores_grace_periods_but_catches_stale_windows`).
